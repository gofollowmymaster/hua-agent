# Shared 包设计规范

本文规定 `packages/shared` 中共享类型和工具的设计规则。

## 内容准入

只有满足以下条件的内容才放入 shared：

- 至少有一个明确跨包消费者，或即将同时被 API 与 RAG Admin 使用。
- 类型或工具语义稳定，不频繁跟随单个页面或单个 Service 内部实现变化。
- 不依赖 NestJS、Vue、Prisma、Redis、BullMQ、axios 实例或浏览器/Node 专属运行时。

## 导出规则

- 统一从 `src/index.ts` 导出公开类型和工具。
- 不暴露内部临时文件路径作为稳定 API。
- 删除或改名导出前，先搜索所有 workspace 消费者。

## 类型规则

- 共享类型应表达跨端契约，而不是复制后端数据库模型细节。
- 不把 Prisma model 原样作为前端契约。
- 不把前端 UI 状态类型放入 shared，除非后端也真实需要同一语义。

## 依赖规则

- shared 保持无框架依赖。
- 新增依赖前确认是否会影响 API 或前端构建环境。
- 不在 shared 中读取环境变量、创建客户端或执行 I/O。

## 变更检查

- 是否确有跨包复用需求。
- 是否从 `src/index.ts` 导出。
- 是否避免泄漏后端内部模型或前端 UI 状态。
- 是否验证所有消费者。

## Why

业务 Agent 目前将整段回答写入同一个 text part，并在历史回放时把所有工具结果放在正文之前。文本、思考和工具过程交错时，用户无法按实际发生顺序阅读。

## What Changes

- 为每条新助手消息持久化有序 parts，覆盖思考、状态、工具结果和文本片段。
- 流式输出在非文本事件打断后创建新的 text part，避免 SDK 合并正文。
- 历史接口返回 parts；RAG Admin 优先按 parts 原顺序回放，旧记录保留现有兼容展示。

## Non-goals

- 不迁移或猜测旧会话中工具与正文的原始交错位置。
- 不修改知识问答聊天协议或共享 ChatDemo 布局。

Listing/Offer监控

## 功能介绍

1. 系统每日自动监控1次所有“生效中”的Offer，当检测到Offer的“产品规格”和“装箱数量”异常时，实时发送异常通知给您配置的人员，让其能快速跟进解决。
2. 系统每日自动监控2次您配置需要监控的Listing，当检测到Listing“Buybox变动”、“内容变动”、“价格变动”、“可售状态变动”、“配送时间变动”和“下架/变狗”时，实时发送异常通知给您配置的人员，让其能快速跟进解决。

> - Buybox变动异常包括：Buybox丢失、1P/VC Offer消失；
> - 内容变动异常包括：图片不存在、标题内的所有单词出现差异、热销榜单类目出现差异、Bullet Point出现差异、Bullet Point小于5条、Bullet Point不存在、A+图片不存在；
> - 价格变动异常是指：亚马逊前台List Price与系统MSRP不一致；
> - 可售状态变动异常是指：Listing详情页显示Currently Unavailable 没有任何有效的（可被消费者购买的）Offer信息;
> - 配送时间变动异常包括：免费配送时间或者最快配送时间超过当前太平洋时间的五天后（不包括五天）；
> - 下架/变狗是指：Listing页面404;

## 注意事项

1. 系统每天检测异常的时间不固定，每个产品每天监控的时间也不固定；
2. 以ASIN维度，某个ASIN第一次检查到异常，则生成一条数据，且状态为待处理，后续该ASIN再次检查到异常，仅更新数据不生成新的记录，就算之前的状态是已处理（记录状态变为部分处理）；
3. 若一个ASIN，某一个异常类型（粒度到异常类型），之前一次检查有异常，并且还未标记为“已处理”，新的一次检查，发现这个异常不存在了（亚马逊自动取消异常或者您们有人工处理），则系统自动把此条异常记录标记为“已处理”，操作人为“系统”（相当于系统自动触发了标记“已处理”操作）；
4. 暂不支持按产品负责人通知，只能所有产品配置统一的通知人员；

#### 单条处理异常

> - 当前“待处理”状态，可标记为“已处理”和“暂不处理”；
> - 当前“暂不处理”状态，可标记为“已处理”和“待处理”；
> - 当前“已处理”状态，不支持再继续处理；
>
> 异常数据生成逻辑：
>
> - 若一个ASIN，某一个异常类型+业务模式+异常详情为待处理/暂不处理，又监控出该异常类型+业务模式+异常详情时，则覆盖原数据，更新最近更新时间；
> - 若一个ASIN，某一个异常类型+业务模式+异常详情为已处理，又监控出该异常类型+业务模式+异常详情时，则生成一条新数据，状态为“待处理”；
> - 若一个ASIN，某一个异常类型+业务模式+异常详情，之前一次检查有异常，并且还未标记为“已处理”，新的一次检查，发现这个异常不存在了（亚马逊自动取消异常或者我们有人工处理），则系统自动标记为“已处理”，操作人为“系统”（相当于系统自动触发了标记“已处理”操作）；

## 常见问题

### 为什么添加监控产品后，列表没有数据？

**答：**仅当产品检测到过异常，才会出现在列表中。

### 为什么某条异常记录，没有人标记为“已处理”，系统自动变为了“已处理”状态？

**答：**当新的一次检查，发现这个异常不存在了（亚马逊自动取消异常或者您们有人工处理），则系统自动把此条异常记录标记为“已处理”，并记录操作日志，操作人为“系统”。

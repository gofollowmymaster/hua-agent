# RAG Admin 样式规范

本文规定 RAG Admin 的样式组织和 UI 使用规则。

## 样式入口

- 全局样式放在 `src/styles/global.css`。
- 页面或组件私有样式优先放在对应 `.vue` 文件中。
- 跨页面复用样式再考虑沉淀到 `styles/`。

## UI 组件

- 优先使用 `@aplus-frontend/ui` 组件，这是 RAG Admin 的默认 UI 组件来源。
- `@aplus-frontend/antdv` 作为公司组件体系的一部分使用；只有 aplus UI 组件无法满足场景时，再考虑 Ant Design Vue 能力或已有封装。
- 原生 HTML 控件仅用于组件库没有合适控件、或语义/可访问性明显更合适的场景。
- 表格、分页、表单、弹窗、提示等常见控件应保持同一交互风格。
- 不新增第二套同职责 UI 框架。
- 新增组件封装前先搜索是否已有 aplus UI 或项目内既有组件可复用。

## 可维护性

- 避免在多个页面复制大段样式。
- 避免依赖脆弱的深层选择器覆盖第三方组件；确需覆盖时限制作用域。
- 保持布局在常见桌面宽度下可读，避免文本和按钮重叠。
- 样式类名使用语义化 kebab-case，优先体现模块和职责，例如 `assistant-history-item`。
- 页面样式不要污染全局；确需全局样式时放入 `src/styles/global.css` 并说明适用范围。

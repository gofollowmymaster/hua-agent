# 数据与集成规范

## 数据库与事务

- 请求使用 `get_db` 提供的 `AsyncSession`，service 不持有跨请求 session。
- 每次读取、更新和删除租户数据都必须包含 `tenant_code`；通过 id 查询也不能省略。
- 父子资源同时校验父资源归属和子表租户，避免只凭外键读取跨租户数据。
- 一个业务原子操作内完成必要写入并显式 commit；失败后继续复用 session 前必须 rollback。
- 批处理允许单项失败继续时，每项必须有清晰事务边界和失败结果。
- 不在本项目中创建迁移或运行时建表。

## 原生 SQL

- 所有动态值使用命名参数，禁止字符串拼接和 f-string 构造 SQL。
- JSONB 使用 `CAST(:value AS jsonb)`，传入 `json.dumps` 后的字符串。
- pgvector 使用 `CAST(:vector AS vector)`，传入 JSON 数组格式。
- 全文检索明确指定 `zhparser`，并对空分词结果进行处理。
- upsert 必须写明冲突键、允许更新的字段和 `RETURNING` 结果。
- 长 SQL 应使用多行文本并配套针对租户、排序和边界条件的测试。

## Redis

- key 模板集中定义，业务模块不散写同类 key。
- 租户状态必须包含 `{tenant}`；非租户 key 需要在设计中明确其全局语义。
- TTL 必须来自明确业务语义，禁止无说明的永久缓存。
- 限流返回值按“是否已经超过限制”解释。
- 幂等状态至少区分处理中、完成和失败，并明确失败是否允许重试。
- 批量读取和删除使用 SCAN，不使用生产阻塞型 `KEYS`。
- pattern 删除必须设置长度或命名空间保护，并按固定批次执行。

## 异步和阻塞操作

- 请求链路优先使用异步数据库、Redis、HTTP 和模型客户端。
- 同步 SDK、密码计算、文档解析和大量文件 I/O 必须通过 `asyncio.to_thread`、任务队列或其他隔离方式离开事件循环。
- 外部调用必须配置连接和读取超时；批量调用应设置并发上限。
- 不在 async 方法中使用阻塞 sleep。
- 后台任务不得依赖已经结束的请求上下文，必须显式传入租户和身份信息。

## 文件安全

- 上传文件先校验数量、扩展名和字节大小，再写入受控目录。
- 使用 `Path.resolve()` 后验证目标仍位于允许根目录内，防止路径穿越。
- 冲突文件名使用有界重命名策略，不覆盖未知现有文件。
- 预览、删除和重新入库都先校验数据库资源归属与文件路径。
- 临时文件应在成功、失败和取消路径中清理。

## 外部服务

- 模型、embedding、rerank 和飞书凭据通过 `Settings` 获取，不作为函数参数在日志中传播。
- 可选集成采用延迟校验，核心服务启动不应因未启用功能缺少凭据而失败。
- 同步 SDK 调用通过线程隔离，并把 SDK 原始响应转换为最小项目结构。
- 可重试与不可重试错误需要区分；重试必须有次数、退避和幂等边界。
- 单元测试默认 mock 外部服务，实时调用只能通过显式开关启用。

## 日志与敏感信息

- 请求日志只记录 method、path、status、duration 等元数据。
- 不记录密码、token、secret、Authorization、请求体、知识内容、原始工具参数或完整工具结果。
- 工具与模型日志只允许名称、调用 id、耗时、状态和有界摘要。
- 错误日志保留诊断上下文，但面向客户端的消息必须去除内部细节。
- 配置诊断只输出配置字段名，不输出配置值。

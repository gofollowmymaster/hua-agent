# 当前实现差距

本文登记当前代码与目标规范之间仍存在的已知差距。已经完成的 lifespan 资源归属、领域目录迁移、原生 SQL repository 下沉、外部模型客户端注入、异常脱敏、受限线程池文件处理和基础 PostgreSQL/Redis 集成环境不再列为差距。

## 优先级定义

- P1：可能影响安全、并发可靠性或接口稳定性，应优先安排。
- P2：主要影响可维护性、可测试性或长期演进，应在相关模块变更时处理。
- P3：局部一致性问题，可随邻近代码修改逐步收敛。

## P1 稳定响应仍存在宽泛字典类型

证据：部分领域 service 仍返回 `dict[str, Any]` 或 `list[dict[str, Any]]`，且为避免改变现有序列化结果，尚未为全部 JSON route 声明 `response_model`。

目标：在逐接口快照证明输出完全一致后，将稳定 payload 收敛为领域 Pydantic model；动态 provider 结果和内部事件使用 TypedDict 或判别联合。

## P2 集成覆盖仍需扩展

证据：隔离 Compose 已覆盖 PostgreSQL 扩展、事务、基础租户数据和 Redis TTL/限流/幂等，但文档解析、真实检索、完整会话持久化和资源关闭的集成路径仍不完整；模型与飞书继续默认 mock。

目标：逐域补充 repository、文件解析、会话顺序和生命周期测试；实时模型与飞书保持显式 opt-in。

## P3 错误消息和术语不完全统一

证据：兼容接口历史消息同时存在中文和英文。为保持现有客户端契约，本次没有统一改写全部业务错误文本。

目标：仅在调用方确认后，以契约测试保护同类校验、未找到、未认证和配置错误的稳定消息模板。
